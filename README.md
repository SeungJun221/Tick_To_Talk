# Tick To Talk

Unity 6000.6.0f1 / URP / Netcode for GameObjects 2.13.0.

## 실행

`Assets/TickToTalk/Scenes/TickToTalk_Prison.unity`를 엽니다.
Windows 빌드는 Unity 메뉴 **Tick To Talk → Build Windows Client And Server**로 생성합니다.

1. 서버 PC에서 `Builds/Windows/Start_Server.cmd` 실행.
2. 플레이어 두 명은 각자의 PC에서 빌드 폴더 전체를 복사한 뒤 `Start_Client.cmd` 실행.
3. 서버 PC의 IP를 입력하여 접속. 서버 PC에서 테스트할 때만 `127.0.0.1` 사용.
4. 두 명 모두 **준비 완료**를 누르면 5분 라운드 시작.

이 구현은 Unity 전용 서버에 직접 접속합니다. Unity Gaming Services Relay/Lobby/Vivox가 연결된 상태가 아닙니다. 다른 네트워크에서 접속하려면 서버의 UDP 7777 포트가 접근 가능해야 합니다(서버 방화벽 및 공유기 포트 전달 설정). 클라우드 배포는 별도입니다. 서버는 플레이어 슬롯을 차지하지 않습니다.

## 조작과 규칙

- WASD 이동, 마우스 시점, E 상호작용, ESC 커서 해제.
- 바깥쪽 벽의 단말: 본인의 폭탄. 북쪽 벽의 단말: 상대방 폭탄의 매뉴얼.
- 강화 유리 앞 나무 테이블의 마이크 근처에서 E: 발언권 요청. 발언 중 E: 일찍 종료.
- 발언권은 한 명만 소유. 최대 10초 발언 후 전체 마이크 10초 잠금. 일찍 종료하거나 테이블에서 멀어져도 10초 잠금.
- 발언권이 없으면 마이크 녹음 및 전송을 중지합니다. 상대는 수신만 가능합니다.
- 운영체제의 기본 마이크를 사용합니다. 마이크 권한을 허용하고 헤드폰을 사용하세요.
- 치환 암호 → 배선 순서 → 좌표 행렬 → 동시 차단의 4단계. 두 폭탄은 별도로 생성됩니다.
- 이전 단계의 정답을 종이에 기록하세요. 다음 단계 계산에 필요합니다.
- 오답마다 20초 감소. 두 사람 합산 오답 3회 또는 5분 초과 시 실패.
- 마지막 정답은 두 사람이 5초 이내에 모두 제출해야 성공. 늦으면 차단 준비만 해제되므로 다시 제출할 수 있습니다.
- 두 사람 중 한 명이 연결을 끊으면 진행 중 라운드 종료.
- 재도전은 두 사람 모두 다시 준비. 완전히 나갔다 재접속하려면 두 클라이언트 모두 연결 종료 후 다시 접속.

## 구현

- 서버가 이동 범위, 상호작용 거리, 발언권, 음성 패킷 중계, 타이머, 오답 및 성공을 판정합니다.
- 각 클라이언트에는 자기 문제와 상대 매뉴얼만 전송합니다. 전체 정답과 랜덤 시드는 서버에 남습니다.
- 실제 음성은 16 kHz mono PCM16, 20ms 단위, Unity Transport의 unreliable sequenced 메시지로 중계합니다. 서비스급 음성 코덱/에코 제거/암호화/인증은 추가되지 않았습니다.
- 캐릭터는 보유 중인 ithappy Creative Characters FREE 팩을 사용하며, A/B 프리팹과 걷기 애니메이터를 만듭니다.
- 네트워크 의존성이 없는 퍼즐 규칙 검증은 **Tick To Talk → Verify Puzzle Rules**로 실행합니다.

## 주요 파일

- `Runtime/PuzzleSession.cs`: 서버 퍼즐 생성 및 라운드/발언권 규칙.
- `Runtime/NetworkSession.cs`: 전용 서버와 클라이언트 메시지, 이동 및 거리 검증.
- `Runtime/TableVoice.cs`: 실제 마이크 입력, 음성 전송과 수신 재생.
- `Runtime/PrisonPresentation.cs`: 1인칭 조작, 한국어 UI와 캐릭터 표현.
- `Editor/BuildPrison.cs`: 씬·프리팹 생성, Windows 빌드, 규칙 검증.

실제 두 PC 사이의 마이크/스피커 통화와 외부 인터넷 접속은 해당 장비 및 네트워크에서 확인해야 합니다.
